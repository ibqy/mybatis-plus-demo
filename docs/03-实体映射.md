## 1. Entity 是数据库行在 Java 中的表示

核心示例是 [User.java](../src/main/java/com/xb/mybatisplus/entity/User.java#L24)。一条查询结果会被映射成一个 `User`，多行会成为 `List<User>`。

```java
@TableName("demo_user")
public class User {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String name;
}
```

## 2. 常用映射注解

| 注解 | 项目示例 | 作用 |
|---|---|---|
| `@TableName` | [User 第 24 行](../src/main/java/com/xb/mybatisplus/entity/User.java#L24) | 类对应哪张表 |
| `@TableId` | [User 第 28 行](../src/main/java/com/xb/mybatisplus/entity/User.java#L28) | 标记主键并指定生成策略 |
| `@TableField` | [自动填充字段](../src/main/java/com/xb/mybatisplus/entity/User.java#L44) | 字段配置、自动填充或排除非表字段 |
| `@Version` | [version 字段](../src/main/java/com/xb/mybatisplus/entity/User.java#L55) | 标记乐观锁版本列 |
| `@TableLogic` | [deleted 字段](../src/main/java/com/xb/mybatisplus/entity/User.java#L62) | 标记逻辑删除列 |

字段名不符合驼峰规则时可显式指定：`@TableField("user_name")`。非数据库字段使用 `@TableField(exist = false)`。

## 3. 主键策略

本项目使用 `IdType.AUTO`，依赖 MySQL 自增。常见选择：

- `AUTO`：数据库自增，直观，适合单库入门。
- `ASSIGN_ID`：MyBatis-Plus 生成分布式 ID，常见实现是雪花算法。
- `INPUT`：必须由调用方赋值。

主键策略必须与表结构一致。例如实体写 `AUTO`，数据库却没有自增，插入就可能失败。

## 4. Java 类型选择

实体字段优先使用包装类型 `Integer/Long`，因为它们能表示 `null`。更新时 `null` 常表示“不修改此字段”；基本类型 `int` 的默认值 0 无法区分“未传”和“明确传 0”。

时间字段使用 `LocalDateTime`，而不是旧的 `Date`。数据库、JDBC URL 和应用时区要一致，项目 JDBC URL 指定了 `serverTimezone=Asia/Shanghai`。

## 5. Entity 和 DTO 为什么分开

创建接口只允许客户端提供姓名、年龄和邮箱：[CreateUserRequest](../src/main/java/com/xb/mybatisplus/dto/CreateUserRequest.java#L21)。如果直接接收 `User`，客户端可能提交 `deleted=1`、伪造 `version` 或修改内部状态。

```text
请求 JSON → DTO（外部边界）→ Service 转换 → Entity（数据库边界）
```

DTO 上的 `@NotBlank`、`@Email` 属于快速反馈；数据库的非空和唯一约束属于最终数据完整性保障，两者互补。

## 6. 自动映射规则

`map-underscore-to-camel-case: true` 会完成：

```text
created_at → createdAt
updated_at → updatedAt
```

如果列名和属性差异更大，就需要 `@TableField` 或 XML `resultMap`。

## 7. 动手实验

1. 在表中设计一个 `nickname` 可空列，并在实体添加对应属性。
2. 设计一个只用于接口显示、数据库不存在的 `displayName` 字段，使用 `exist = false`。
3. 思考金额为什么不应使用 `double`，而应选择数据库 `DECIMAL` 与 Java `BigDecimal`。
