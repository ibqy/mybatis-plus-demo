## 1. 自动填充

实体使用 `@TableField(fill = ...)` 声明填充时机：[User 时间字段](../src/main/java/com/xb/mybatisplus/entity/User.java#L44)。真正提供值的是 [AuditMetaObjectHandler](../src/main/java/com/xb/mybatisplus/config/AuditMetaObjectHandler.java#L19)。

```text
执行 insert
 → MyBatis-Plus 发现 INSERT 填充字段
 → MetaObjectHandler 写入 createdAt/updatedAt
 → 生成并执行 SQL
```

`strictInsertFill` 通常只在当前值为空时填充，避免覆盖业务明确设置的值。

## 2. 乐观锁

乐观锁适合“冲突不常发生”的场景。两个操作者都读到 `version=0`：

```text
A 更新：WHERE id=1 AND version=0 → 成功，version 变 1
B 更新：WHERE id=1 AND version=0 → 影响 0 行，提示重新读取
```

实体标记见 [`@Version`](../src/main/java/com/xb/mybatisplus/entity/User.java#L55)，插件见[乐观锁配置](../src/main/java/com/xb/mybatisplus/config/MybatisPlusConfig.java#L28)，业务检查见[更新结果判断](../src/main/java/com/xb/mybatisplus/service/impl/UserServiceImpl.java#L80)。

乐观锁不会自动重试业务操作。盲目重试可能覆盖别人的修改，通常应提示用户查看最新数据后决定。

## 3. 逻辑删除

实体标记见 [`@TableLogic`](../src/main/java/com/xb/mybatisplus/entity/User.java#L62)，全局值配置见 [application.yml](../src/main/resources/application.yml#L28)。

通用查询自动增加 `deleted=0`，通用删除改写成 `deleted=1`。但手写 XML SQL 必须自己处理逻辑删除条件，本项目已在[自定义 SQL](../src/main/resources/mapper/UserMapper.xml#L18)显式添加。

逻辑删除的代价：

- 数据仍占空间；
- 唯一索引设计更复杂；
- 所有手写 SQL 都必须遵守过滤规则；
- 它不是审计系统，也不能替代备份。

## 4. 防全表更新与删除

[BlockAttackInnerInterceptor](../src/main/java/com/xb/mybatisplus/config/MybatisPlusConfig.java#L32) 会阻止明显缺少条件的全表更新/删除。它是一道护栏，不代表任何带 `WHERE` 的 SQL 都安全，例如 `WHERE id > 0` 仍可能覆盖全表。

## 5. 插件顺序

MyBatis-Plus 插件会依次改写 SQL。项目顺序是：

```text
乐观锁 → 防全表操作 → 分页
```

分页一般靠后，让其他插件先完成 SQL 处理。新增租户、数据权限等插件时，要阅读官方说明并用最终 SQL 验证顺序。

## 6. 动手实验

1. 连续两次用相同 version 更新同一用户，第二次应返回 409。
2. 逻辑删除后直接在数据库查看该行，再通过普通接口查询。
3. 临时写一个无条件 update Wrapper，在隔离数据库验证防攻击插件，再删除实验代码。
